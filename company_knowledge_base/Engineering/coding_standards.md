# Engineering Coding Standards
All production code must have meaningful tests for important business logic.

Pull requests should be small enough to review effectively.

Variable and function names should communicate intent.

Secrets, API keys, passwords, and tokens must never be stored directly in source code.

New external dependencies require security and license review when appropriate.

Developers should prefer clear, maintainable implementations over unnecessary abstraction.

Code review comments should focus on correctness, security, maintainability, and consistency.
